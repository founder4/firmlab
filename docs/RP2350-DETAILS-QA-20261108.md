# PICOBIN decoder evidence in the workbench — 2026-11-08

The existing RTOS detail view now distinguishes function targets attempted from
function decodes completed. A native disclosure exposes the finite attempt and
invocation budgets, pending/excluded targets and observed/omitted edge counts.
A second disclosure retains original bytes and source mnemonics from up to 16
listed decoder substitutions, with an explicit displayed/available count when
more were stored. Neither view claims execution or whole-image coverage.

New stored fields remain optional forever. A legacy result gets no invented
attempt/completion counters; missing or invalid counters/mnemonics remain
unrecorded, and an explicit zero remains zero. Instruction addresses include
helper functions, so they are labelled as instruction addresses, not entrypoints.
Go/Composer VEX changes and the API decoder's proof rules are outside this UI change.

The view preserves the existing palette and detail hierarchy. Native summaries
remain keyboard-operable and have a 44-pixel minimum hit height. Source fields
flow into readable rows on a narrow screen instead of breaking a hexadecimal
address across narrow table columns. No request, lane or analysis action changes.

Validation on the built application:

- 32 focused `DeepAnalysisDetails` DOM tests pass, including partial results,
  old absent fields, invalid counters, a 16-of-20 bound and missing legacy mnemonics.
- Web build and repository Biome/static audits pass.
- `PicobinDetails.qa.mjs` serves ephemeral synthetic HTTP responses on loopback
  with no database and no deployed API. Its 12 Chromium cases cover English and
  Spanish, dark and light themes, and widths 320/390/1440. Both evidence
  disclosures open through actual keyboard Enter, the source mnemonic is visible,
  expected counters remain distinct, and the document has no horizontal overflow.
  There are no console exceptions, failed requests or HTTP errors.
- The new evidence notes' computed contrast is 7.14:1 in dark and 6.39:1 in light.
  This is a measurement of those new notes, not a contrast audit of every old label.
- Mobile source evidence and desktop/full-page captures were inspected. Browser
  touch capability is synthesized; this does not prove physical mobile keyboards,
  Safari, screen-reader announcements or actual firmware/runtime behavior.

Run after `pnpm --filter @firmlab/web build`:

```sh
node apps/web/src/components/PicobinDetails.qa.mjs /tmp/firmlab-picobin-qa
```

Campaign evidence is under `picobin-ui-{baseline,after}` with the adjacent
build/test/Biome logs. The baseline lacked the new evidence displays. An initial
narrow table was replaced after inspecting its broken address wrapping; only the
final responsive rows are committed. Capture full pages from scroll zero and
separate source rows so fixed application chrome does not obscure the evidence.

After the decoder-integrity follow-up, the failure counter is labelled “Decode
failures / stopped continuations” in both languages. It can include several
internal stops in one attempted function; it is not a count of failed function
targets. The target-attempt and completed-function counters remain independent.
Focused DOM and built-browser checks were rerun after this wording change.
